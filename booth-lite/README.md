# booth-lite — 소규모 부스용 파생 버전 (축전 앱의 하위 프로젝트)

[2026 원주 수학과학축전 스탬프 랠리](../README.md) 앱에서 파생한, **부스 7개짜리 소규모 행사용** 버전이다. 지도가 없고, 폰이 없는 저학년 어린이가 많아 **부스마다 둔 태블릿으로 직원이 도장을 찍는 운영**이 핵심이다. 축전 앱과 코드베이스를 공유하되 서버(Supabase)·호스팅(Vercel)은 완전히 분리해 데이터가 섞이지 않는다.

## 축전 앱과 다른 점

| 영역 | 축전 앱 | booth-lite |
|---|---|---|
| 부스 | 95개, 배치도 지도·경로·히트맵 | 7개, 지도 없음(`CONFIG.miniMode`) — 지도 탭·배치도·대시보드 히트맵 숨김 |
| 등록 항목 | 학교·구분·학년·이름·성별 고정 | **소속·나이·연락처** + 이름. 관리자 › 행사 설정에서 항목별 **사용/필수** 토글(`settings.regFields`) |
| DB 열 | school·grade·gender | 같은 열을 뜻만 바꿔 사용(school=소속, grade=나이, gender=연락처) → SQL 구조 변경 없음 |
| 집계 | 학년군(초저·초고·중·고·성인) | 나이대(어린이 ~12 · 청소년 13~18 · 성인 19~) |
| 수기 도장 | 관리자 › 선물 수령 안의 보조 기능 | **부스 태블릿 모드**(아래) |
| 설문 | 완주 → 설문 → 교환권 | 행사 설정의 **설문 사용** 토글. 끄면 완주 즉시 교환권, 선물 수령도 설문을 보지 않음 |
| 기본 데이터 | 축전 일정·리플릿·설문 문항 | 비움 / 일반 행사용 문항 |
| 서버 | 축전 Supabase | 별도 Supabase 프로젝트(무료 플랜 2개째), 같은 `supabase_setup.sql` 1~16절 |

## 부스 태블릿 (관리자 › 수기 도장)

폰이 없는 어린이를 위해 부스마다 태블릿을 한 대 두고 직원이 찍는다.

1. 관리자로 로그인한 태블릿이 **부스 QR을 한 번 찍으면 그 부스에 고정**된다(`sessionStorage`). 부스 고르기 화면은 분류 색 띠·큰 번호의 타일 격자
2. **이름 두 글자**를 치면 바로 카드가 뜬다 → [도장] 한 번 → 큰 확인 화면(도장 칸 진행, 5초 뒤 자동 복귀) → 다음 어린이
3. 카드마다 **1~7 부스 칸**으로 어느 부스 도장을 받았는지 보이고, 이 부스에 이미 있으면 버튼이 [이미 찍음]으로 잠긴다(`visitor_stamps` RPC, 1분 캐시)
4. 검색창이 비어 있을 땐 **"방금 다른 부스에서 도장 찍은 아이들"**(최근 10분, 이 부스 미도장)이 미리 떠 있어 보통은 이름도 안 치고 탭 한 번이면 끝난다. 부스별 명단 RPC(`admin_booth_visitors`)를 부스마다 40줄씩 받아 합쳐 SQL 추가 없이 구현, 20초 갱신
5. 처음 온 아이는 [처음 왔어요] → 등록 항목 입력 → **등록과 도장을 한 번에**. 등록 직전 같은 이름을 조회해 "이 아이예요(기존에 도장) / 다른 아이예요(새로 등록)"를 고르게 해 **같은 아이의 이중 등록**을 막는다. 소속까지 같으면 빨간 경고
6. 같은 이름의 다른 아이는 소속·나이·부스 칸·등록 시각으로 구분한다

등록은 `visitor_create`(방문객 RPC, 관리자 폰의 `S.me` 는 건드리지 않음), 도장은 `admin_add_stamp`(토큰·90초 간격 검사 없음)로 들어간다.

## 축전 앱과 동기화하는 법 (`sync/`)

파생본은 축전 앱 원본에 **텍스트 치환 스크립트를 순서대로 적용**해 만든다. 축전 쪽에서 보안·버그를 고치면 다음 절차로 그대로 가져온다.

```
축전 앱 HTML 을 booth-lite_스탬프앱.html 로 복사
python -I sync/1_미니모드.py  …  python -I sync/11_동명이인_부스상황제거.py   (순서대로)
CONFIG 의 supabaseUrl · supabaseAnonKey 를 이 프로젝트 값으로 채움
powershell -File 배포.ps1
```

| 단계 | 내용 |
|---|---|
| 1 미니모드 | 제목·CONFIG·부스 시드 7개·분류 1개, 지도 탭/버튼/라우트 제거, 관리자 탭 교체, 관리자가 부스 QR 찍으면 수기 도장으로 |
| 2 수기도장 | 수기 도장 함수 초기판 |
| 3 소속나이이름 | 등록 항목·표·CSV·대시보드 라벨, 나이대 집계 |
| 4 등록항목설정 | `regFields` 토글, 라우터 조각별 디코딩(축전이 이미 고쳤으면 건너뜀), 기본 일정·자료 비움 |
| 5 수기도장_태블릿 | 부스 고정 흐름, 대시보드 히트맵 숨김 |
| 6 번호표_UI | 카드·확인 화면 UI, 자동 검색 |
| 7 설문설정 | `surveyOn` 토글, 기본 문항 |
| 8 부스고르기_타일 | 타일 격자 |
| 9 방금온아이들 | 최근 10분 목록, `DB.recentVisitors` |
| 10 부스별도장표시 | 1~7 부스 칸, [이미 찍음] |
| 11 동명이인_부스상황제거 | 같은 이름 확인 화면, 부스 상황 띠 제거 |

스크립트는 원문 문자열을 찾아 바꾸므로 축전 쪽 해당 줄이 바뀌면 `assert` 로 멈춘다. 그 치환만 손보고 다시 실행하면 된다. 3·5단계는 대시보드가 이미 적용돼 있으면 건너뛴다.

## 설치

1. Supabase 새 프로젝트 → SQL Editor 에 `supabase_setup.sql` 전체 실행(1~16절)
2. `booth-lite_스탬프앱.html` 과 `운영대시보드.html` 의 `supabaseUrl` · `supabaseAnonKey` 채우기
3. `배포.ps1` 실행(Vercel 로그인 필요). 서버에 부스가 없으면 관리자 › 부스에서 한 번 저장해 토큰 발급
4. 관리자 `#/admin` (초기 비밀번호 1234 → 데이터 탭에서 변경), 행사 설정에서 행사명·날짜·등록 항목·설문 사용 여부

## 검증

- 로컬(Playwright, `supabaseUrl` 비운 복사본): 태블릿 흐름 32체크, 등록 항목·설문 토글 18체크, 콘솔 에러 0
- 실서버 e2e 16체크: QR 딥링크 등록 → 도장, 90초 간격 거절, 관리자 QR → 태블릿, 최근 목록·부스 칸·검색·등록, 대시보드 — 끝나면 `admin_reset` 으로 정리(실데이터 0건 상태에서만)

## 만들면서 바꾼 결정

- **번호표 카드 폐기**: 아이에게 번호표(QR 카드)를 주고 태블릿으로 찍는 방식까지 구현했으나(SQL 17절), 인쇄·배부·번호 연결의 운영 부담이 커서 뺐다. 대신 이름 검색 + 최근 목록 + 부스 칸으로 같은 목적을 달성
- **수기 도장 1차 폐기**: 검색·등록 칸이 나열된 관리 화면은 현장 흐름과 맞지 않았다 → "부스 고정 → 찾기 → 확인 → 다음"의 한 흐름으로 재설계
- **부스 상황(혼잡도) 띠 제거**: 태블릿에선 필요 없다는 운영 판단
